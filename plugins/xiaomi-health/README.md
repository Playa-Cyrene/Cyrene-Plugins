# 小米运动数据同步服务（非官方插件）

> ⚠️ **免责声明**：本插件为第三方开源项目，**与小米公司无关联、未获小米授权**。"小米运动健康 / Mi Fitness"为小米公司商标，此处仅用于说明数据来源与兼容性。数据同步基于公开接口实现，**仅供个人学习与研究使用**。

让 Cyrene 连接你的小米运动健康（CN 区）账号，读取**你本人**的步数 / 睡眠 / 心率数据，并在对话、定时播报、早安问候与长期记忆中自然地使用这些信息。

## 功能

- **扫码登录**：用已登录小米账号的「小米运动健康」App 扫码授权；凭证经系统密钥链加密保存，**不明文落盘**。
- **两个查询工具**（随插件自动注册，安装即自带）：
  - `xiaomi-health_query` —— 查询今日 / 最近 N 天的步数、睡眠、心率。
  - `xiaomi-health_status` —— 查询连接与同步状态。
- **对话内健康感知**（可开关）：把健康摘要注入对话上下文，Agent 会主动调用工具回答身体相关问题。
- **定时主动播报**：可选频率（每天 1~12 次或每条 ≈ 每小时）、风格（自然关心 / 带具体数字）、播报指标。
- **独立早安问候**：可单独设定时间，并可选是否携带健康信息；实时查不到时会回退参考最近一条健康记忆。
- **健康写入长期记忆（L2）**：可选，逐条追加、不覆盖、可被语义检索，让日常对话与主动寒暄也能想起你的近况。
- **后台定时同步**（间隔可配）。
- **一键退出登录**：清除加密凭证、本地同步数据与本插件创建的定时任务。

## 安装

**方式一 · 导入 ZIP（推荐）**

1. 到 [Releases](../../releases) 下载 `xiaomi-health-vX.Y.Z.zip`（或把本仓库根目录打包成 zip）。
2. Cyrene → **设置 → 插件 → 导入 ZIP**（或经安装市场）。
3. 在插件列表里**启用**「小米运动数据同步服务」。

**方式二 · 从源码**

```bash
git clone https://github.com/ahwhshen/xiaomi-health-plugin.git
```

把仓库根目录（含 `manifest.json` 的那层）整体复制到 Cyrene 用户插件目录 `userData/plugins/xiaomi-health/`，重启或热重载后在插件列表启用。

**启用后**：打开插件面板扫码登录；勾选播报 / 早安 / 记忆后，对应任务会出现在宿主「定时任务」面板，需你**手动点【启用】**。

## 依赖与前提

- 一个小米账号 + 已登录该账号的「小米运动健康」App（用于扫码授权）。
- 数据来自小米云端：设备需先把运动 / 睡眠**同步到云端**，插件才能读取；刚醒来时昨夜睡眠可能尚未同步。
- **仅在应用运行期间**同步与播报，不在后台拉起。
- 宿主需提供定时任务（`scheduler`）与密钥（`secrets`）能力（`manifest.json` 已声明 `deps`）。
- 「健康写入长期记忆」的语义检索依赖宿主的向量嵌入模型；若模型缺失会退化为关键词检索。

## 为什么目前只支持小米

华为 / 荣耀 / vivo 的官方健康接口要求**企业主体 + 资质审核 + 开发者应用授权**，个人开发者申请不到；OPPO 走商务定向接入；苹果 HealthKit 只在**设备端**、不开放第三方云端读取。而小米可以通过官方 App **扫码授权 + 公开接口**直接读取你本人账号下的数据，无需申请资质，所以先做了小米。其它品牌后续可能通过「导出文件本地导入」的方式支持。

## 隐私与数据

- 只读取**你本人**账号下的健康数据。
- 登录凭证通过 `ctx.deps.secrets` 加密保存；退出登录即清除；**凭证与同步数据都不进版本库**（见 `.gitignore`）。
- **插件自包含，不修改 Agent 本体**：工具、对话注入、定时任务都通过宿主公开的插件 API 注册。

## 网络访问与数据存储（审核须知）

- **网络访问**：仅对小米官方 3 个域名发起 HTTPS 请求，用途单一，不向任何第三方发送数据，也不开放任何监听端口：
  - `account.xiaomi.com` —— 扫码登录授权与凭证换取；
  - `sts-hlth.io.mi.com` —— 换取访问健康数据所需的临时凭证（STS）；
  - `hlth.io.mi.com` —— 拉取**你本人**账号下的步数 / 睡眠 / 心率。

  请求全部经由 Node 内置 `fetch` 完成，**不引入任何第三方 HTTP 库**。
- **数据存储**：入口代码**不调用 `fs` 读写任何文件**，全部持久化都走宿主提供的隔离接口：
  - `ctx.deps.secrets` —— 加密保存小米登录凭证（会话令牌与安全密钥），仅存本机，退出登录时删除；
  - `ctx.storage` —— 保存用户偏好（`prefs`）、最近同步时间戳（`lastSync`）、早安确认标记（`morningNoticeAck`），由宿主隔离在本插件的私有存储目录内；
  - 健康数据本身只在内存中缓存，不额外落盘；仅当你勾选「写入长期记忆」时，才通过宿主的 `write_memory` 能力写入 L2 记忆层。
- **子进程**：**不启动任何子进程**（代码中不存在 `child_process` / `spawn` / `exec` / `fork`）。
- **窗口**：仅在用户主动打开面板 / 连接时，由宿主创建一个加载插件自带 `ui.html`（本地文件，非外部 URL）的设置窗口，用法与官方示例 `system-status` 一致。
- **自包含性**：运行时依赖仅有 Node 内置模块（`node:path`、`node:crypto`）、同目录内的 `lib/xiaomi.cjs`，以及宿主提供的 `electron`；**不 require 任何未打包的 npm 包**。

## 合规提示

数据同步基于逆向的消费者端点（`hlth.io.mi.com`），**可能不符合小米《用户服务协议》**。请在了解并接受该风险的前提下、仅用于个人学习与研究，不要用于商业用途或对外提供服务。

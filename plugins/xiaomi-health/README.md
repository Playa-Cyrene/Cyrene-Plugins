让 Cyrene 连接你的小米运动健康（CN 区）账号，读取**你本人**的步数 / 睡眠 / 心率数据，并在对话、定时播报、早安问候与长期记忆中自然地使用这些信息。

## 功能

- **扫码登录**：用已登录小米账号的「小米运动健康」App 扫码授权；凭证经系统密钥链加密保存，**不明文落盘**。
- **两个查询工具**（随插件自动注册，安装即自带）：
  - `xiaomi-health_query` —— 查询今日 / 最近 N 天的步数、睡眠、心率，可能返回健康摘要。
  - `xiaomi-health_status` —— 查询连接与同步状态，已连接时返回账号 `user_id`，有缓存时还会返回健康摘要。
- **对话内健康感知**（默认开启，可关闭）：自动向宿主的对话、定时任务及动态生成上下文提供健康摘要。此开关仅控制自动注入；关闭后，普通聊天仍可通过已启用的健康查询工具读取数据。如需禁止工具访问，请在宿主工具设置中禁用 `xiaomi-health_query` 和 `xiaomi-health_status`。
- **定时主动播报**：可选频率（每天 1~12 次或每条 ≈ 每小时）、风格（自然关心 / 带具体数字）、播报指标。
- **独立早安问候**：可单独设定时间，并可选是否携带健康信息；实时查不到时会回退参考最近一条健康记忆。
- **健康写入长期记忆（L2）**：可选，逐条追加、不覆盖、可被语义检索，让日常对话与主动寒暄也能想起你的近况。
- **后台定时同步**（间隔可配）。
- **退出登录**：删除插件保存的登录凭据、健康缓存、同步元信息与关联任务；不会删除宿主中的健康记忆、聊天记录或动态，具体范围见下文。

## 安装

**方式一 · 导入 ZIP（推荐）**

1. 从[官方收录列表](../../README.md#已收录插件)下载维护者发布的小米健康插件 ZIP；待审核版本需等合并打包后再下载。
2. Cyrene → **设置 → 插件 → 导入 ZIP**（或经安装市场）。
3. 在插件列表里**启用**「小米运动数据同步服务」。

**方式二 · 从源码**

```bash
git clone https://github.com/ahwhshen/xiaomi-health-plugin.git
```

把仓库根目录（含 `manifest.json` 的那层）整体复制到 Cyrene 用户插件目录 `userData/plugins/xiaomi-health/`，重启或热重载后在插件列表启用。

**启用后**：打开插件面板扫码登录。定时播报、早安问候和健康记忆三个功能**默认关闭**；勾选并保存后才会创建对应宿主任务，新任务需在宿主「定时任务」面板**手动点【启用】**后才开始运行。修改已有任务的时间、频率、提示内容或工具范围会撤销原有授权，需重新确认启用；执行设置未改变的已启用任务保持原状态。以宿主面板显示为准。

## 依赖与前提

- 一个小米账号 + 已登录该账号的「小米运动健康」App（用于扫码授权）。
- 数据来自小米云端：设备需先把运动 / 睡眠**同步到云端**，插件才能读取；刚醒来时昨夜睡眠可能尚未同步。
- **仅在应用运行期间**同步与播报，不在后台拉起。
- 宿主需提供定时任务（`scheduler`）与密钥（`secrets`）能力（`manifest.json` 已声明 `deps`）。
- 「健康写入长期记忆」的语义检索依赖宿主的向量嵌入模型；若模型缺失会退化为关键词检索。

## 为什么目前只支持小米

华为 / 荣耀 / vivo 的官方健康接口要求**企业主体 + 资质审核 + 开发者应用授权**，个人开发者申请不到；OPPO 走商务定向接入；苹果 HealthKit 只在**设备端**、不开放第三方云端读取。而小米可以通过官方 App **扫码授权 + 公开接口**直接读取你本人账号下的数据，无需申请资质，所以先做了小米。其它品牌后续可能通过「导出文件本地导入」的方式支持。

## 隐私与数据

- 只读取**你本人**账号下的健康数据。
- 登录凭证通过 `ctx.deps.secrets` 保存；退出登录时删除。凭证与同步数据不随插件发布。
- 健康摘要和工具查询结果会交给宿主使用；是否发送给远程模型或其他处理服务取决于宿主配置。启用前请确认宿主的数据处理设置。
- **聊天健康感知**：将摘要自动提供给宿主上下文，供对话、定时任务和动态生成参考。关闭只停止自动注入，不禁用查询工具，也不删除宿主已经收到的内容。
- **定时播报与早安**：任务将健康查询结果交给宿主生成消息；「自然关心（不报数字）」只改变输出风格，不阻止查询结果用于模型处理。早安启用携带健康信息时，实时数据不可用会检索当天或前一天的健康记忆。
- **长期记忆**：任务把健康数据交给宿主生成并追加 L2 记忆，供日后对话、主动寒暄和早安检索；模型处理和语义检索是否使用远程服务取决于宿主配置。关闭并保存后停止后续写入，不会自动删除已有记忆。
- **插件自包含，不修改 Agent 本体**：工具、对话注入、定时任务都通过宿主公开的插件 API 注册。

## 退出、停用与历史数据删除

- **退出登录**：删除插件保存的登录凭据、内存健康缓存、同步元信息（`lastSync` 置空），并删除本插件的播报、早安和健康记忆任务、关闭这三个选项。其他偏好及早安提示确认标记保留，再次连接需重新扫码。
- **停用插件**：停止请求、定时同步并清理运行状态，不等于退出登录；已保存的登录凭据、偏好与同步元信息保留。
- **宿主历史内容**：退出、停用或关闭长期记忆功能都不会删除已经写入宿主的健康记忆、聊天记录或动态。这些历史内容需在宿主的「记忆」、聊天记录和动态对应面板另行删除。

## 网络访问与数据存储（审核须知）

- **网络访问**：插件直接请求小米账号及健康服务，主要服务域名如下：
  - `account.xiaomi.com` —— 扫码登录授权与凭证换取；
  - `sts-hlth.io.mi.com` —— 换取访问健康数据所需的临时凭证（STS）；
  - `hlth.io.mi.com` —— 拉取**你本人**账号下的步数 / 睡眠 / 心率。

  此外会访问认证流程返回的扫码、轮询和重定向地址，不能将访问范围理解为仅上述三个域名。认证请求传输登录认证信息，健康请求传输账号标识及查询参数并接收健康数据。插件不开放监听端口，请求经由 Node 内置 `fetch` 完成，不引入第三方 HTTP 库。

  健康摘要、工具查询结果（连接状态结果包含账号 `user_id`）会交给宿主；是否继续发送给远程模型或其他处理服务由宿主配置决定，插件无法保证这些数据仅在本机处理。
- **数据存储**：入口代码**不调用 `fs` 读写任何文件**，全部持久化都走宿主提供的隔离接口：
  - `ctx.deps.secrets` —— 加密保存小米登录凭证（会话令牌与安全密钥），仅存本机，退出登录时删除；
  - `ctx.storage` —— 保存用户偏好（`prefs`）、最近同步时间戳（`lastSync`）、早安确认标记（`morningNoticeAck`），由宿主隔离在本插件的私有存储目录内；
  - 插件自身只在内存中缓存健康数据，不额外写健康数据文件；摘要和查询结果交给宿主后，可能出现在宿主聊天记录、任务结果或动态中。勾选并保存「健康写入长期记忆」、且在宿主启用对应任务后，该任务会通过 `write_memory` 写入 L2 记忆层；这些宿主历史内容不属于插件退出登录的清理范围。
- **子进程**：**不启动任何子进程**（代码中不存在 `child_process` / `spawn` / `exec` / `fork`）。
- **窗口**：仅在用户主动打开面板 / 连接时，由宿主创建一个加载插件自带 `ui.html`（本地文件，非外部 URL）的设置窗口，用法与官方示例 `system-status` 一致。
- **自包含性**：运行时依赖仅有 Node 内置模块（`node:path`、`node:crypto`）、同目录内的 `lib/xiaomi.cjs`，以及宿主提供的 `electron`；**不 require 任何未打包的 npm 包**。

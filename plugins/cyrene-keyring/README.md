# 钥匙环（cyrene-keyring）

把密码、2FA 验证码、API Key 和安全笔记收进一个本机加密库。默认用 Windows Hello 打开，无操作五分钟自动锁回去（可在面板里调整或关掉）。

面板分成「条目」「设置」「说明」三页：条目页管添加、搜索和查看；设置页管自动锁、Windows Hello、主密码与备份迁移；说明页写清四档权限、已知限制和免责声明。

> 当前版本 **0.4.0**：加密库、锁状态机、四类条目、面板、加密导出导入、Hello 优先解锁与阶梯限流、三种手动 2FA 导入、从旧插件迁移（含 cyrene-totp）。0.4.0 起 Agent 只看得到密文引用，取用要过一次一密令牌。

## 条目类型

| 类型 | 存什么 | Agent 默认能不能发请求 |
| --- | --- | --- |
| `password` | 账号、密码、网址 | 不能，只给面板 |
| `totp` | secret、位数、周期、算法 | 能，本次解锁免确认 |
| `api_key` | Key、服务名、用途 | 能，本次解锁免确认 |
| `note` | 自由文本 | 不能，只给面板 |

面板上 `totp` 显示为「2FA 验证码」，也就是双因认证里的动态码。展开条目就直接给明文，旁边有复制按钮，复制的是当前这 6 位码，不是 secret。列表每 1.5 秒会刷新一次状态，但内容没变时不会重绘，所以验证码不会闪。

添加 2FA 条目时，直接在「添加」弹窗里粘贴 otpauth 链接、填 secret，或识别二维码截图，解析后确认字段再保存。

每条可以单独改 Agent 权限，四档：

| 档位 | Agent 能做什么 | 值去哪 |
| --- | --- | --- |
| `panel-only` | 连取用请求都发不出 | 只在面板里 |
| `ask` | 每次都要在面板点「允许」 | 剪贴板，工具只回「已复制」 |
| `session` | 首次确认后可勾「本次解锁都允许」，之后同次解锁内直接执行 | 剪贴板，工具只回「已复制」 |
| `plaintext` | 不进待确认区，解锁后直接取 | 明文直接进工具返回值 |

后两档都只在本次解锁内有效，锁定即失效。`plaintext` 的明文会进入对话上下文，只建议给一次性或随时可以轮换的凭据。旧库里的 `always` 会在读取时自动迁到 `session`。

## 加密

```
主密码 --scrypt(N=2^17, r=8, p=1)--> KEK(32B) --AES-256-GCM--> 包裹 DEK(32B)
DEK --AES-256-GCM--> 条目库
```

- 库文件里没有明文，也没有 KEK
- 头部字段（KDF 参数、盐、条目数、更新时间）全部进 AAD，改任何一项都会解密失败
- 换主密码只重新包裹 DEK，不重加密整库
- DEK 只在主进程内存里，锁定即清零
- 新建或修改主密码时至少 12 位；老库用短密码仍能解锁，改密码时才按新规则校验

## 锁

- 无操作自动锁默认 5 分钟，可在面板里选 5 / 15 / 30 分钟、1 / 2 / 4 小时，或自定义 1 到 1440 分钟；设为「不自动锁」后，只保留手动锁定和关闭宿主两个结束条件
- 面板最小化或隐藏后按设定时间自动锁，默认 10 秒；可选 10 秒 / 20 秒 / 30 秒 / 1 分钟 / 2 分钟 / 3 分钟 / 10 分钟 / 1 小时，也可以自定义 5 到 3600 秒。切回来就取消
- 手动锁定立即清零内存里的 DEK
- 主密码尝试按阶梯限流：1 小时 → 1 天 → 1 周 → 1 个月 → 1 季度 → 1 年 → 4 年 → 8 年，每档 5 次；某一档用完，要等这一档的窗口走完才进下一档
- Hello 连续 3 次没通过，折算 1 次主密码尝试
- 计数和窗口锚点写在库文件头部的 `guard` 字段里，只往前走
- 系统时间往回拨会被判成跳变，当前窗口直接耗完
- 往前拨也有边界：只有当它足以让当前窗口提前结束、并且这一档已经用过配额时才算跳变。输错一次、隔几分钟再试这种正常间隔不会被误判
- 跳变换不来新的尝试次数，只会多锁一个窗口。面板会把「往前/往回调了多久」写出来
- 日期被拨到一个月以外再拨回来，锚点拉回真实时间并升一档，避免把库永久锁死
- 冷却期间可以用 Windows Hello 重置：锁屏页点「用 Windows Hello 重置冷却」，通过一次就把阶梯清零。主密码没有这条通道
- 面板每 1.5 秒轮询一次状态，锁定时自动回到锁屏页

## 解锁流程

默认是 **Hello 优先**：打开面板就自动唤起一次 Windows Hello，通过直接进主界面。没通过、或者用户取消，才落下主密码输入框，并提供「重试 Windows Hello」。锁屏页始终留一个「改输入主密码」的入口，防止 Hello 卡在系统层时进不去。

主界面的「Windows Hello」设置里有一个 **主密码进入模式** 开关，默认关闭。开启后锁屏页会同时给出 Hello 和主密码，输入任意一个都能进，且不会自动弹 Hello。

开启 Hello 的方式：建库时如果设备支持，会自动用 DPAPI 包一份 DEK 存进库文件；也可以在设置里手动开关。Hello 通过后解出这份 DEK，再由 `openWithDek` 打开条目。

这条边界要清楚：

- Hello 负责证明「坐在电脑前的是号主」
- DPAPI 绑定的是 Windows 账户，不是 Hello 本身
- 因此，能在这个账户下跑代码的进程，理论上可以绕过 Hello 直接解 DPAPI
- 它防的是「别人拿到这台电脑」，不防「本机恶意软件」

关掉 Hello 解锁会把 `helloWrap` 清空，主密码始终有效。修改主密码不影响 Hello，因为 DEK 没变。

限流计数同样存在库文件头部。它挡的是「有人坐在这台电脑前反复猜」，挡不住「把库文件复制走离线爆破」——后者只能靠主密码本身足够长。

## Agent 取用

| 工具 | 作用 |
| --- | --- |
| `cyrene-keyring_list` | 列条目，只返回标题、类型、账号，不含秘密 |
| `cyrene-keyring_get` | 返回 `secret://<id>` 引用，外加类型、标题、长度；任何类型都不返回明文 |
| `cyrene-keyring_use` | 在面板里发起一次取用请求，等用户点「允许」 |
| `cyrene-keyring_open` | 打开面板 |

引用只是一句标识，本身不含可解密的内容。Agent 拿着它做不了什么，必须由你在面板上放行：

1. Agent 调用 `use`，面板顶部出现「等待你确认」，显示条目标题、类型、要做什么、以及它给的理由
2. 你点「允许」后，主进程签发一次性令牌：32 字节随机数，60 秒过期
3. 令牌立刻被兑换成一次动作 —— 复制类直接把值写进剪贴板（30 秒后清空），验证码类在面板上显示
4. 兑换完令牌立即作废，同一个令牌不能再用第二次
5. 你点「拒绝」、令牌过期、或者锁库，待确认请求和所有未用令牌一起清空

工具返回值里始终没有明文。待确认列表最多挂 20 条，防止 Agent 刷屏。

所有取用写审计，保留 200 条，面板里能翻。审计只记条目标题、动作和令牌前 8 位，不记值。

## 加 2FA 验证码

面板上有三种方式，随便挑一种：

1. **粘贴链接**：把 `otpauth://totp/...` 整条粘进去。服务名、账号、算法、位数、周期都会从链接里读出来。
2. **手动输入**：填服务名、账号、Base32 secret，再选算法、位数、周期。
3. **截图识别**：选图片或直接从剪贴板读图，面板用 `jsQR.js` 在本地解出二维码内容，识别到 `otpauth` 链接就自动添加。

三条路都只在本机处理，不会把 secret 发到任何地方。旧插件里的 2FA 走「从旧插件导入」，secret 同样按 Base32 校验，和手动添加共用一套「类型 + secret」去重规则。

## 从旧插件迁移

面板「备份与迁移」区有「扫描旧插件数据」。它会读这几个来源：

| 来源 | 读什么 | 怎么解 |
| --- | --- | --- |
| `cyrene-vault` | 保险箱 4 条（含邮箱、AI、云服务凭据） | PowerShell DPAPI |
| `gh-vault` | GitHub 令牌 | Electron safeStorage |
| `bdpan-vault` | 百度网盘 API Key | Electron safeStorage |
| `cyrene-totp` | 2FA secret | Electron safeStorage |
| `mail-send` | `app-settings.json` 里的 SMTP 账号与授权码 | 明文配置项 |

流程是先扫描出清单（只含数量，不含任何秘密），确认后再点「开始迁移」。导入按 `类型 + secret` 去重，重复的跳过；迁移不会改动旧插件的数据，旧文件保持只读。迁移报告只回条数，不打印任何明文。

注意 `gh-vault`、`bdpan-vault`、`cyrene-totp` 的条目需要 Electron 的 `safeStorage`，只能在 Cyrene 进程里解；纯 Node 环境下这几项会显示为 0 条。

## 导出与导入

导出时用另外设置的密码重新加密一份库文件，主密码不会跟着出去。导入按 `类型 + 秘密值` 去重，重复的跳过。

## 已知限制

- `ask` 每次都会进待确认区；`session` 只在首次确认，之后同次解锁内免确认；`plaintext` 完全不进待确认区，这是有意的取舍
- 令牌是进程内存里的短期凭据，重启 Cyrene 就全没了；这符合预期，也意味着不能跨进程复用
- 用完配额后关机很久再回来，会被判成时间跳变，多锁一个窗口。纯本地拿不到可信时间源，宁可按可疑处理，恢复通道只有 Hello
- 不支持浏览器自动填充
- 不支持云同步
- 换设备只能靠导出文件 + 导出密码
